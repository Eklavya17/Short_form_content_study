# RQ3: feed clustering study

Does showing same-topic videos back to back keep people watching or tire them out,
and after a like, should the next video be more of the same or something different?
Each participant scrolls three feeds that differ only in how they pick the next topic:

| Feed | Picks the next topic by | A like or a long watch |
| --- | --- | --- |
| A | Random topic not played in the last 3 videos | Does nothing |
| B | Stay or switch, by chance | Makes staying **more** likely |
| C | Stay or switch, by chance | Makes staying **less** likely |

The full design and its decisions live in the RQ3 Build Plan doc. This file is the
map of the code. RQ3 lives on the `rq3` branch; the RQ1 pilot on `main` is untouched.

New files are marked **new**; nothing from RQ1 is moved or changed.

The engine (`config`, `catalog`, `scoring`, `feeds`, `simulation`) imports no Flask or
database code, so the simulator and the server run the same logic.

## Build order

### Part 1: build the feeds (no server needed)

| Step | What | Where |
| --- | --- | --- |
| 1 | Parse topic, duration, structure, stage, loop and payoff times for all 44 clips; list clips to mark by hand | `rq3/build_catalog.py`, `rq3/catalog.py` |
| 2 | Similarity placeholder: same topic = similar, until VCA vectors exist | `rq3/feeds.py` (`_pick_clip`) |
| 3 | Swipe adjustment g for story, loop and hybrid clips | `rq3/scoring.py` |
| 4 | Feed A: cooldown of 3 | `rq3/feeds.py` |
| 5 | Feeds B and C: update p, clip, reset, run cap | `rq3/feeds.py` |
| 6 | Topic choice on a switch: softmax over topic scores | `rq3/feeds.py` |
| 7 | Forced switches: run cap or topic exhausted | `rq3/feeds.py` |
| 8 | Decision record: p, draw, kind, state snapshot | `rq3/feeds.py` |
| 9 | Simulator and its three checks; pick block length | `rq3/simulation.py` |
| 10 | Tests for every rule | `tests/` |

### Part 2: run the study and measure swipes

| Step | What | Where |
| --- | --- | --- |
| 1 | Tables: participants, blocks, impressions, events | `rq3/storage.py` |
| 2 | Player event logging | `static/rq3/player.js` |
| 3 | Log the start time once, not on every resume | `static/rq3/player.js` |
| 4 | Swipe route: score, update state, pick next, save decision | `rq3/web.py` |
| 5 | Preload two candidates; log load delay | `rq3/web.py`, `static/rq3/player.js` |
| 6 | Study pages: consent, interest, practice, blocks, surveys | `templates/rq3/`, `rq3/web.py` |
| 7 | Balanced assignment of the 6 feed orders | `rq3/storage.py` |
| 8 | Admin CSV export | `rq3/web.py` |
| 9 | Full-screen swipe player; test on iPhone, Android, laptop | `static/rq3/player.js` |
| 10 | Analysis | `rq3/analysis.py` |

### Later: clustering

Run the VCA pipeline (VideoContentAnalysis_CHI26) on the campus cluster GPU, then
average each clip's 40 token vectors, compute cosine similarity and run k-means here.
That replaces the same-topic placeholder from Part 1, step 2.

## Conventions

- Numbers that might be tuned go in `rq3/config.py`, never inline.
- One function per rule, named for what it does; a docstring says the rule in words.
- Type hints on every function; dataclasses for records passed between modules.
- Store raw facts in the database; compute scores at analysis time.
- Unbuilt functions raise `NotImplementedError` naming the step that builds them.

## Running

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
pytest
```

Once built: `python -m rq3.build_catalog` and `python -m rq3.simulation`.
